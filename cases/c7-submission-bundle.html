C7

最小可复现递交包

把第 0 章的 renv、第 4 章的追溯清单、第 5 章的验证证据和第 9 章的 ADRG 拼成一个真能跑通的目录：一条命令产出 XPT、Dataset-JSON、ASCII 程序、闭源包文本束、执行日志、ADRG 骨架与 md5 清单。

背景与学习目标

C1 关心「结果对不对」，C7 关心「别人能不能把同样的结果再跑一遍」。脚本为 cases/c7_submission_bundle.R，在仓库根目录执行 Rscript cases/c7_submission_bundle.R；产物写到 cases/out/c7_bundle/（已加入 .gitignore，不进版本库）。学完你应当能够：

  • 目标 1：说清七层证据链分别锁什么、每层的产物落在哪个目录。
  • 目标 2：亲手生成 XPT v5 与 Dataset-JSON v1.1，理解两者在 2026 年递交中的双轨关系。
  • 目标 3：写出一份能照着重建环境的 ADRG 骨架，并用 manifest.tsv 做产物自检。
数据源：复用 C1 的共享推导 cases/common.R，输入为 pharmaversesdtm::dm 合成 SDTM（306 行），不联网、无外部数据下载。依赖：必需 admiral / pharmaversesdtm / dplyr / diffdf / renv；可选 xportr / datasetjson / pkglite / logrx（缺失时脚本自动降级并如实打印）。本站实跑捕获使用 R 4.5.0，可选包通过 C7_R_LIBS 指向的私有库加载，未改动全局 R 库。

步骤 1：分析数据集与双编程自检

root <- if (grepl("cases$", getwd())) ".." else "."
source(file.path(root, "cases", "common.R"))
adsl <- suppressWarnings(derive_adsl())          # admiral + pharmaversesdtm
qc   <- diffdf(adsl, suppressWarnings(derive_adsl()), keys = "USUBJID")
cat("ADSL", nrow(adsl), "x", ncol(adsl), "| ITTFL=Y", sum(adsl$ITTFL == "Y"), "\n")
cat("[QC] diffdf issues:", diffdf_has_issues(qc), "\n")
# 实跑捕获（R 4.5.0）
-- Step 1 analysis dataset --
ADSL 306 x 14 | ITTFL=Y 254
[QC] diffdf issues: FALSE
逐行解读：
  1. 直接复用 C1 的 derive_adsl()，把注意力留给「包装」而不是再写一遍推导；路径自适应保证从根目录或 cases/ 下都能跑。
  2. 两次独立调用做 diffdf 自检，等价于 SAS 的 PROC COMPARE——可复现的第一步是证明同一份代码能重复产出同一份数据。

步骤 2：七层证据链（L1–L7）

这一节是 C7 的核心。注意 L2：脚本在 reviewer_env/ 里新建裸项目并 snapshot，而不是把申办方的 lockfile 复制过来——这是第 9 章 9.3 与 J&J ADRG 附录的关键差别。

# L1 Git SHA
sha <- system2("git", c("-C", shQuote(normalizePath(root)), "rev-parse", "--short", "HEAD"),
               stdout = TRUE, stderr = FALSE)[1]

# L2 在审评端重建锁文件
renv::init(project = reviewer, bare = TRUE, restart = FALSE)
renv::snapshot(project = reviewer, prompt = FALSE)
setwd(old_wd); .libPaths(old_lib)   # renv::init 会切换 wd 与库路径，必须恢复

# L3/L4 会话与包版本
writeLines(capture.output(sessionInfo()), file.path(logs, "session.txt"))
vers <- vapply(used, function(p) as.character(packageVersion(p)), character(1))

# L5 输入指纹  L6 执行日志  L7 ADRG
write.csv(pharmaversesdtm::dm, file.path(inputs, "dm_snapshot.csv"), row.names = FALSE)
md5 <- substr(unname(tools::md5sum(snapshot)), 1, 12)
logrx::axecute(file.path(programs, "run.R"), log_name = "run.log", log_path = logs)
writeLines(adrg, file.path(docu, "adrg.txt"))

-- Step 2 environment evidence (L1-L7) --

L2 renv.lock        : rebuilt in reviewer_env/
   contains R/renv  : TRUE / TRUE
L3 sessionInfo      : logs/session.txt
L4 package versions : 9 of 9 available -> logs/package_versions.tsv
L5 input md5        : 9c19ef853ff4 (inputs/dm_snapshot.csv)
L6 execution log    : logs/run.log (logrx)
逐行解读：
  1. renv::init() 会切换工作目录并把 .libPaths() 指到项目私库——这是实战中最容易踩的坑：后续相对路径全部错位、可选包突然"找不到"。脚本里显式 setwd(old_wd) 与 .libPaths(old_lib) 恢复。
  2. logrx::axecute() 生成的日志自带 logrx 版本、文件 hash、session info 与所用函数清单，比手写 Rscript ... >> log 2>&1 更接近审评端需要的执行证据。
  3. 输入指纹取的是落盘的只读快照而不是内存对象，这样审评员能拿同一个文件校验 md5。
SAS 误区：把「环境锁」理解成「把一个文件随包发过去」。真正要交付的是配方 + 可核验的产物：安装脚本、R/Rtools 版本、在本机重建锁文件的指示，以及能证明重建成功的 sessionInfo 与日志。

步骤 3：XPT v5 与 Dataset-JSON v1.1 双轨

# XPT v5：递交级做法用 xportr + metacore 从 spec 取 label/format/length
xportr::xportr_write(adsl, path = file.path(datasets, "adsl.xpt"), domain = "ADSL")

# Dataset-JSON v1.1 必须显式提供列级元数据（itemOID/name/label/dataType）
mk_cols <- function(df, domain = "ADSL") {
  dt <- vapply(df, function(x) {
    if (inherits(x, "Date")) "date" else if (is.integer(x)) "integer" else
    if (is.numeric(x)) "float" else if (is.logical(x)) "boolean" else "string"
  }, character(1))
  data.frame(itemOID = paste0("IT.", domain, ".", names(df)), name = names(df),
             label = names(df), dataType = unname(dt), length = NA_integer_,
             keySequence = ifelse(names(df) == "USUBJID", 1L, NA_integer_))
}
# date 列必须转成 ISO-8601 字符，不能传 Date 对象（v1.1 校验要求）
adsl_json <- as.data.frame(lapply(adsl, function(x)
  if (inherits(x, "Date")) format(x, "%Y-%m-%d") else x))
dj <- datasetjson::dataset_json(adsl_json, name = "ADSL", columns = mk_cols(adsl),
                                 version = "1.1.0")
datasetjson::write_dataset_json(dj, file = file.path(datasets, "adsl.json"), pretty = TRUE)
# 实跑捕获（R 4.5.0）
-- Step 3 data deliverables --
XPT v5              : adsl.xpt 45280 bytes
Dataset-JSON 1.1.0  : adsl.json 103264 bytes
Note                : keep XPT too - v1.1 not yet in Pinnacle 21 (Pilot 5)
为什么要双轨：R Consortium Pilot 5 用 datasetjson 替换全部 XPT 后，发现 Dataset-JSON v1.1 当时尚未被 Pinnacle 21 支持，于是与 FDA 沟通后改用 XPT 完成验证，并把这一点写进 ADRG。本案例照此保留两份数据。另外，第一次尝试写 Dataset-JSON 时脚本报了错——dataType = "date" 要求输入列为 ISO-8601 字符而非 Date 对象——这个报错本身就是「新格式需要列级元数据」的最好教材。

步骤 4：ASCII 程序与闭源包打包

# SDTCG v5.7 §4.1.2.10：源码以单字节 ASCII 文本递交
writeLines(c("# Program: adam_adsl.txt - derive ADSL (single-byte ASCII)",
             "source('cases/common.R')", "adsl <- derive_adsl()",
             "stopifnot(nrow(adsl) > 0, !anyDuplicated(adsl$USUBJID))"),
           file.path(programs, "adam_adsl.txt"))
pkglite::verify_ascii(file.path(programs, "adam_adsl.txt"), quiet = TRUE)

# 闭源包：pkglite 文本束（Pilot 1）或 .zip（Pilot 3 / eCTD v9.3）
pkglite::collate(pkg = pkgdir, pkglite::file_ectd(), pkglite::file_auto("R")) %>%
  pkglite::pack(output = file.path(programs, "r0pkg.txt"))
# 实跑捕获（R 4.5.0）
-- Step 4 program bundle --
ASCII program       : adam_adsl.txt (verify_ascii = TRUE )
pkglite text bundle : r0pkg.txt 564 bytes
.zip package        : skipped (no external zip tool); .txt bundle used
逐行解读：
  1. verify_ascii() 是 pkglite 自带的校验函数，直接对应 SDTCG 的 ASCII 要求——比肉眼检查靠谱，也方便进 CI。
  2. 本机没有外部 zip 可执行程序，所以 .zip 分支被如实跳过，用文本束兜底。脚本不隐瞒降级：这一点和「断网环境下 riskmetric 指标记 NA」是同一种诚实，正是可审计流水线该有的行为。

测验：C7 为什么要「在 reviewer_env/ 里新建 lockfile」，而不是把申办方的 renv.lock 复制过去？

选 B。J&J 的 ADRG 附录与 R/Pharma 2026 圆桌都指向同一做法；Pilot 5 还额外说明 Rtools 版本须与 R 版本匹配。FDA 并不禁止 lockfile，问题在于可移植性。
