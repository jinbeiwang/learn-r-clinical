药企常用 R 包地图

全书是按章节逐个实跑讲包的；这一页反过来，按临床数据流水线把包摊开成一张速查表：做某件事该找哪个包、谁在维护、本书哪一章讲过、2026 年的状态如何。适合读完两三章后回来对照，也适合团队做工具选型时当索引。

边界先说清：这些包是行业常用工具，不是"经 FDA 认证/验证"的软件。FDA 不验证编程语言，选择足够可靠的包并验证流程与环境的责任在申办方（见 9.1）。本页的社区公告与治理迁移信息只说明代码归属与维护方式，不构成合规依据；实际递交以公司 SOP、QA/RA 意见与当期法规为准。事实核对于 2026-11-07，来源见章末资源。

PM.1 怎么读这张地图

每张表五列：包（CRAN / GitHub 上的名字）、用途（一句话）、生态 / 维护（谁在主导，跨公司共建会写明）、本书（哪一章实跑讲解，写"仅登记"表示本页只做索引）、状态。

流水线顺序是：原始 EDC → SDTM → ADaM → TLG / 统计 → 交互式审阅 → XPT / Dataset-JSON → 递交包 → 验证与环境证据。读的时候不必从头到尾，直接跳到你要解决的那一步。

命名陷阱：CRAN 包名、GitHub 仓库名、项目简称经常不一致。例如 CRAN 上叫 cardinalfda，仓库是 pharmaverse/cardinal；scda 的数据在 scda.2022 这类年度归档包里；teal 既是框架名也是一个具体包名。写安装脚本和 renv.lock 时以 CRAN 包名为准。

PM.9 2026-11 治理迁移与两个易错点

公告：Roche Open-Source TLG Packages Move to pharmaverse（2026-11-03，Joe Zhu / Dony Unardi，代表 NEST team）。罗氏把一批临床报告与探索分析包从 insightsengineering/ 迁入 pharmaverse/，转为社区共治。官方 "What Packages Have Migrated?" 小节共 15 个包：

分组包
Reporting & Tabulation Foundationformatters、rtables、rlistings、cards、cardx
Analysis & Automation Modulestern、autoslider.core
{teal} ecosystem 核心包teal、teal.code、teal.data、teal.widgets、teal.reporter、teal.slice、teal.logger、teal.picks

对用户意味着什么：官方对 CRAN / Release Users 的原文是 Zero breaking changes —— 已发布版本不变，通过 CRAN 或内部镜像安装时 R 代码无需改动；GitHub 仓库会自动重定向，但建议把开发版引用从 insightsengineering/<pkg> 改为 pharmaverse/<pkg>（如 pak::pkg_install("pharmaverse/teal")），issue 与 PR 也集中到新组织。

易错点一 · 别把社区公告读成验证承诺：11-03 这篇没有出现 "validated environments"，也没有讨论 GxP、再验证或冻结版本，更没有给出 roadmap 或版本号。"零破坏性变化"说的是仓库迁移不改 API，不等于已冻结的验证环境可以跳过变更控制。
真正提到 strengthening its use in validated environments 的是次日续篇 Roche and Appsilon Build on Their Collaboration…（2026-11-04）：Roche 与 Appsilon 共同持有 teal 版权，未来开发方向包括该目标、AI 辅助开发指引以及测试与依赖管理改进 —— 这是未来方向，不是当前已生效的能力或合规声明。已锁定环境仍按 SOP 走变更控制，包来源与版本照旧在 renv.lock / package_versions.tsv 留证（见 9.3 与 C7）。
易错点二 · 不是所有 Roche 系包都迁走了：crane（CRAN 0.3.2 / 2026-06-03，NEST 2.0 新包）仓库仍在 insightsengineering/crane；scda 也仍在 insightsengineering/scda。而 cardinalfda（CRAN 0.3.0 / 2026-09-04）本来就在 pharmaverse/cardinal。判断包的维护状态要看具体仓库，别按公司名一刀切。
scda 状态修正：insightsengineering/scda 的 README 顶部已标注 "scda is deprecated and no longer maintained. Use at your own risk."（本页核对于 2026-11-07）。本书 CH2 2.1 把它列为"年度归档、适合企业做回归测试与验证"是当时的写法，现在不应再作为新项目的推荐数据源；日常教学与单元测试用 pharmaversesdtm / pharmaverseadam，需要版本冻结时把数据快照纳入自己的版本库与验证证据，而不是依赖一个已停止维护的外部包。
# 迁移后：核对已锁定环境里包的来源与版本，比改代码更重要
library(renv)
lock <- renv::lockfile_read("renv.lock")
pkgs <- names(lock$Packages)
print(pkgs)

测验 1：某项目的 renv.lock 里锁着 rtables，同事说"11 月迁到 pharmaverse 了，得赶紧升级并重新验证"，最稳妥的判断是？

选 B。11-03 公告的 Zero breaking changes 只针对已发布版本与仓库迁移；它既没有给 roadmap，也没有谈验证环境，"strengthening its use in validated environments" 是 11-04 续篇里的未来开发方向。已冻结环境的任何变更仍按 SOP 走，包风险评估见 9.5。

测验 2：下面哪一组是本书 CH2 之后仍推荐作为练习数据源的？

选 A。scda 已明确 deprecated 且不再维护；pharmaversesdtm / pharmaverseadam 是 pharmaverse 维护的合成 SDTM / ADaM 数据，也是本书的默认练习数据。
